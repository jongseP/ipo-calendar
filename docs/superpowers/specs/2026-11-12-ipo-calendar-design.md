# 공모주 달력 설계

작성일: 2026-11-12

## 1. 왜 만드나

공모주 청약 일정을 여러 은행·증권 앱과 커뮤니티에서 하나씩 찾아보는 게 번거롭다.
일정을 한곳에 자동으로 모아 달력으로 보고, 내가 청약·보유·매도한 기록을 같이 관리하고 싶다.
주로 **출근길에 폰으로** 확인한다.

## 2. 목표

- 공모주 일정을 자동으로 모아 한 달 달력으로 보여 준다.
- 종목마다 보여 줄 정보:
  - 청약 기간(시작일~종료일)
  - 청약 가능한 증권사(주간사)
  - 최소 청약금액
  - 상장일
- 일정이 정정되거나 청약이 취소되면 자동으로 반영한다.
- 내 기록을 남긴다.
  - 상태: 청약함 → 보유 중 → 매도함
  - 배정 수량
  - 매도 수익
- **나 혼자만** 쓴다. 로그인은 두지 않는다(사용자 결정).

## 3. 하지 않는 것

- 가족·지인과 공유하지 않는다. 사용자가 공유를 검토한 뒤 혼자 쓰기로 정했다.
- 실제 청약이나 매도 주문을 대신 넣지 않는다. 기록만 한다.
- 수요예측 결과 분석이나 청약 추천은 하지 않는다.
- 알림(푸시·메일)은 이번 범위에 넣지 않는다. 필요하면 나중에 추가한다.

## 4. 실패로 보는 경우

- 내 투자 기록(상태·배정 수량·수익)이 페이지 주소를 아는 남에게 보이거나 남이 고칠 수 있다.
- 일정이 바뀌거나 취소됐는데 달력에 예전 일정이 그대로 남아 있다. 특히 내가 청약한 종목에서 이러면 안 된다.
- 폰 화면에서 달력이 잘리거나 옆으로 밀려 읽기 어렵다.

## 5. 화면

- **위쪽: 한 달 달력.** 날짜 칸에 청약 기간과 상장일이 표시된다. 청약과 상장은 색으로 구분한다.
- **아래쪽: 이번 주 목록.** 이번 주에 청약하는 종목과 상장하는 종목을 보여 준다.
- 종목을 누르면 상세 정보가 나오고, 그 자리에서 내 상태·배정 수량·매도 수익을 입력하거나 고친다.
- 내가 청약한 종목은 달력에서 한눈에 구별된다. 상태(청약함·보유 중·매도함)마다 표시가 다르다.
- 일정이 바뀌었거나 취소된 종목은 눈에 띄게 표시한다. 예: 취소선, "정정" 배지.
- 폰 세로 화면이 기준이다.

## 6. 데이터 출처 (2026-11-12 직접 확인)

- **주 출처: 38커뮤니케이션 공모주 청약일정 표**
  - 주소: `https://www.38.co.kr/html/fund/index.htm?o=k`
  - 인코딩: EUC-KR
  - `robots.txt`가 `Disallow:`로 비어 있어서 수집을 막지 않는다.
  - 표에서 읽히는 칸: 종목명, 청약기간(`2026.12.14~12.15` 형식), 확정공모가, 희망공모가, 청약경쟁률, 주간사
  - 예시: `KTE / 2026.12.14~12.15 / - / 19,000~23,000 / NH투자증권`
- **확인 못 함:** 상장일과 최소 청약 주식 수가 어느 페이지에 있는지는 아직 확인하지 못했다.
  38커뮤니케이션 종목 상세 페이지에 있을 것으로 추정한다. 만드는 사람이 먼저 확인해야 한다.
- **보조 출처: DART OpenAPI `estkRs`**(증권신고서 지분증권)
  - 주소: `https://opendart.fss.or.kr/api/estkRs.json`
  - 응답에 `청약기일`, `청약공고일` 항목이 있다(개발 가이드에서 확인).
  - 쓰려면 무료 인증키가 필요하다.
  - 38커뮤니케이션만으로 정정·취소를 충분히 잡을 수 있으면 쓰지 않아도 된다.

## 7. 최소 청약금액

보통 다음 식으로 계산한다.

> 공모가 × 최소 청약 주식 수 × 증거금률(50%)

- 확정공모가가 있으면 확정공모가를 쓴다.
- 확정 전이면 희망공모가 하단으로 계산하고 "예상"이라고 표시한다.
- 이 식은 검증하지 못했다. 만드는 사람이 실제 청약 공고 몇 건과 비교해 확인한다.

## 8. 만드는 방식 (사용자가 정하지 않은 부분은 Claude가 정함)

사용자가 정한 것:
- 따로 여는 웹페이지로 만든다. 구글 캘린더 같은 달력 앱은 쓰지 않는다.
- 혼자 쓴다.
- 화면 구성은 위쪽 달력, 아래쪽 이번 주 목록이다.

Claude가 정한 것(사용자가 바꿀 수 있음):
- **로그인 없음, 서버 DB 없음** (로그인 빼기로 한 뒤 Claude가 바꿈)
  - 종목 일정은 공개 정보라 누구에게 보여도 괜찮다. 그래서 `data/ipos.json` 파일로 저장소에 둔다.
  - 내 기록(상태·배정 수량·수익)은 **폰 브라우저 안(localStorage)에만** 저장한다.
    - 로그인이 없어도 남이 보거나 고칠 수 없다.
  - 대신 생기는 한계:
    - 다른 기기에서는 내 기록이 안 보인다.
    - 브라우저 데이터를 지우면 기록이 사라진다.
    - 그래서 기록을 JSON 파일로 내보내고 다시 불러오는 버튼을 둔다.
  - 여러 기기에서 같이 봐야 하면 그때 Supabase로 옮긴다.
- **수집: GitHub Actions**
  - Python 스크립트가 정해진 시간마다 돈다. 직원 식단 사이트(ncmh-menu)의 `fetch_menu.py` + Actions 방식과 같다.
  - 갱신은 하루 몇 번(예: 오전 7시, 정오, 오후 6시)이면 충분하다고 본다.
  - 수집 결과로 `data/ipos.json`을 갱신해 커밋한다. 종목 하나에 항목 하나를 두고, 같은 종목은 덮어쓴다.
- **정정·취소 처리**
  - 수집할 때마다 이전 값과 비교한다.
  - 청약 기간, 공모가, 상장일이 바뀌면 바뀐 시각과 이전 값을 남긴다.
  - 목록에서 사라진 종목은 바로 지우지 않고 "취소 의심"으로 표시한다.
  - 진짜 취소인지 판단하는 방법은 만드는 사람이 정한다. 예: 철회 공시 확인, 며칠 연속으로 사라짐.
- **화면: 정적 HTML + JS 한 장**
  - 외부 라이브러리 없이 만든다.
  - 배포는 식단 사이트처럼 GitHub Pages를 쓴다.
  - 빌드 도구는 꼭 필요할 때만 쓴다.

## 9. 만드는 사람에게 맡기는 것

- 종목을 구별하는 키(종목명, 종목코드 등)
- 달력 색과 표시 모양
- 수집 실패 시 재시도와 로그 방식
- 매도 수익을 직접 입력할지, 매도가 × 수량 − 공모가 × 수량으로 계산할지
  - 기본은 직접 입력하고, 계산은 보조로 둔다.
